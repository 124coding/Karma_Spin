# 🎰 캐주얼 전략 PvP 슬롯 배틀 (Casual Strategy PvP Slot Battle)

![Game Preview]([인게임_대표_이미지_또는_움짤_링크_삽입])

슬롯머신의 **'무작위성(Randomness)'**과 로그라이크 유물 시스템을 활용한 **'덱빌딩(Deckbuilding) 전략'**이 결합된 1:1 실시간 네트워크 턴제 대전 게임입니다. 운에만 의존하는 것이 아니라, 실시간 상호작용 기믹과 속성 간의 시너지를 통해 다이나믹한 전투를 경험할 수 있습니다.

---

## 📅 프로젝트 개요
- **개발 기간:** 2026.09 ~ 진행 중
- **개발 인원:** 1인 개발 (기획, 프로그래밍, 연출)
- **장르:** 턴제 전략, 보드, 슬롯, PvP
- **사용 기술:** Unity, C#, Unity Relay & Lobby (네트워크 동기화)

---

## ✨ 핵심 게임플레이
* **속성 잭팟(Bingo) 시스템:** 가로, 세로, 대각선 및 클러스터(다중 매칭)를 통해 데미지를 누적합니다.
* **상점 & 유물(덱빌딩):** 매 라운드 종료 시 상점에서 액티브 아이템과 패시브 유물(Relic)을 구매하여 자신만의 슬롯 확률(가중치)을 조작하고 덱을 강화합니다.
* **보드판 침식 및 파훼 기믹:** 상대의 릴을 얼리거나(Water), 덩굴로 오염시키거나(Wood), 돌로 잠그는(Earth) 등의 상호작용이 실시간으로 발생합니다. 특정 속성 잭팟으로 혹은 파훼 방법으로 기믹을 파훼 가능합니다.

## 🛠 핵심 기술 구현 (Core Technology)

이 프로젝트는 네트워크 환경의 **비동기 이슈(Desync)를 방어**하고, 복잡한 보드 게임 룰을 **안정적이고 유연하게 확장**하기 위한 아키텍처 설계에 집중했습니다.

### 1. 비동기 네트워크 턴 동기화 (Race Condition 완벽 방어)
네트워크 딜레이(Ping)로 인해 1P의 데미지 연출이 끝나기 전, 서버가 2P로 턴을 강제 전환할 경우 로컬 소유권(`isMyTurn`)이 꼬여 데미지와 색상이 뒤바뀌는 현상을 방지했습니다.
* **로직과 연출 주체의 완전 분리:** 서버가 통제하는 논리적 턴(`isMyTurn`)과 릴을 회전시킨 실제 연출 주체(`currentSpinnerIndex / didISpin`)를 프로그래밍적으로 격리했습니다.
* **안정성 확보:** 서버 턴이 변경되더라도 진행 중인 코루틴은 최초 스핀 주체를 끝까지 추적하여 정산하므로, 어떠한 지연 환경에서도 UI와 피격 판정의 오차가 발생하지 않습니다.

### 2. 2-Pass 가계산 기반 연쇄 잭팟 (다중 기믹 상호작용)
단일 연산 구조에서는 "화염 잭팟으로 얼음을 파괴하면, 기믹을 파훼하고 잭팟을 인정한다"는 기획을 구현할 수 없었습니다.
* **Dummy Calculation 아키텍처:** 데미지 연산기에 가계산 단계를 도입했습니다.
  1. **1-Pass (스캔):** 제약 상태에서 릴을 탐색하여 '이번 턴에 부서질 얼음 좌표'를 수집(`HashSet` 사용).
  2. **2-Pass (본계산):** 수집된 좌표의 족쇄를 완전히 해제하여(`return null`) 정상 잭팟에 참여시켜 잭팟을 인정.
* **최적화:** 3x3 크기의 고정된 배열과 `HashSet`을 활용하여 시간 복잡도를 `O(1)`에 가깝게 통제, 2-Pass 연산에도 프레임 드랍이 발생하지 않도록 최적화했습니다.

### 3. Data-Driven 아이템 설계 및 커스텀 덱빌딩 슬롯 엔진
* **ScriptableObject 기반 OCP 달성:** 수십 종의 아이템이 메인 매니저에 강결합되지 않도록 `ItemEffect` 추상 클래스를 설계했습니다. 기획자가 코드 수정 없이 인스펙터에서 아이템 기능과 타겟팅을 직접 조립할 수 있습니다.
* **Chunk & Weight 확률 제어:** 단순 무작위 셔플로 인한 잭팟 파편화 문제를 해결하기 위해 **가중치 동적 제어 및 청크(Chunk) 셔플링 알고리즘**을 구현했습니다. 플레이어의 유물 상태에 따라 특정 심볼이 덩어리째 릴에 삽입되어 전략적인 덱빌딩을 유도합니다.

### 4. 결정론적 난수(Deterministic RNG) 및 상태(State) 생명주기 통제
* **RNG 동기화:** 서버가 발급한 공통 Seed 기반으로 타겟팅, 기믹 확산(덩굴 침식) 등을 연산하여 양측 클라이언트의 오차율을 0%로 만들었습니다.
* **Nullable(`bool?`) 기반 유연한 상태 판정:** 빙결(조건부 해제)과 덩굴(즉발 해제)의 판정 시점이 다름을 고려해 `true / false / null` 3단계 인터페이스를 구축, 기믹 해제 시 기본 매칭 룰로 우아하게 권한을 위임합니다.
* **UI 생명주기 격리:** 상점 재진입 시 Stale Data(이전 판의 매진/가격 데이터 등)가 잔존하는 버그를 해결하기 위해 `MarkAsAllCleared` 등 컴포넌트(알파값, 텍스트)를 강제 오버라이드하는 엄격한 UI 초기화 파이프라인을 구축했습니다.
